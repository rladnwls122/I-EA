기능 형태만 벤치마킹한다 — 수치 튜닝은 어차피 우리 데이터로 해야 한다.

## 1. 매쓰플랫 — 쌍둥이·유사문제 ⭐ 채택 (이번 구현의 중심)

**본 것**: 오답 문항과 같은 유형·개념의 변형 문제를 최대 6배수까지 뽑아 재시험을
만드는 기능. "오답 유형만 집중적으로 다시 풀게" 하는 것이 학원 도입의 핵심 이유로
꼽힌다. 콴다도 정답 확인 뒤 유사 문제 풀이로 잇는 동선을 쓴다.

**우리 형태**: `POST /ai-generations`에 `sourceQuestionId` 하나를 추가한다.
- 문제은행형 서비스는 유형 태그로 **미리 만들어 둔** 문항을 꺼내지만, 우리는 생성
  플랫폼이므로 **원본 문항을 시드로 LLM이 변형**을 만든다. 재고가 없어도 되고,
  유형 분류 체계(매쓰플랫은 6단계)를 새로 만들 필요도 없다.
- `inputParams`가 Json이라 **스키마 변경 없음**. 기존 비동기 파이프라인(BullMQ·
  스냅샷·재생성)을 그대로 탄다.
- 변형의 정의를 프롬프트 계약으로 고정한다: 같은 개념·유형·난이도, 다른 소재·수치·
  정답 위치. "번호만 바꾼 복제"와 "다른 개념으로 이탈" 둘 다 실패로 간주.

**왜 이 형태인가**: 이 저장소의 정체성이 "문항을 만들어 주는 도구"다. 경쟁 서비스의
유사문제가 증명한 학습 가치를, 우리가 이미 가진 생성 경로의 파라미터 하나로 얻는다.

## 2. 산타 — 축별 취약 분석 리포트 ⭐ 채택 (세션 결과 화면)

**본 것**: 응시 직후 "어느 유형에서 잃었나"를 보여 주고 다음 학습을 그 축으로
잇는 흐름. 매쓰플랫도 유형별 성취도 분석을 수업 관리의 축으로 쓴다.

**우리 형태**: 제출된 세션 결과에 **태그별·난이도별 정오 집계**를 붙인다.
- 집계 로직은 오답노트(`/me/notes`)에 이미 있는 패턴의 세션 스코프 축소판이다.
  전 기간 누적(오답노트)과 "방금 본 시험"(세션 결과)은 묻는 질문이 다르다 —
  후자가 비어 있었다.
- 점수 예측·IRT 같은 모델 기반 기능은 **비채택**: 응시 데이터가 모여야 의미가
  있고, 지금 만들면 수치가 거짓말을 한다.

## 3. Anki·클래스카드 — 간격 반복(SRS) ⭐ 채택 (기존 복습 큐 업그레이드)

**본 것**: Anki SM-2는 정답할 때마다 간격을 늘리고(1일 → 6일 → ×ease), 클래스카드는
암기→리콜→스펠 단계 반복으로 같은 원리를 단순화해서 쓴다.

**우리 형태**: `review-state.util.ts`의 고정 간격(X=+1일, TRIANGLE=+3일, 2연속 정답
즉시 마스터)을 **누진 사다리**로 바꾼다: 오답 1일 → 정답 3일 → 정답 7일 → 마스터
(3연속). ease factor는 **비채택**.
- SM-2 전체(ease factor·가변 배수)를 안 가져오는 이유: 문항은 단어 카드보다 재노출
  비용이 크고(풀이 시간), ease 튜닝은 사용 데이터 없이는 "ease hell"(낮은 ease에
  갇혀 과잉 반복) 같은 부작용만 복제한다. 사다리 단계 추가는 `consecutiveCorrect`
  컬럼이 이미 있어 **스키마 변경 없이** 끝난다.
- 2연속 → 3연속 마스터로 올리는 근거: 현행 규칙에서는 TRIANGLE에서 한 번만 맞으면
  영구 졸업이라, 1·3일 두 간격밖에 경험하지 못한다. 간격 반복의 핵심인 "길어진
  간격을 버텨야 졸업"이 성립하려면 최소 한 단계(7일)가 더 필요하다.

## 4. 족보닷컴 족보클라우드 — 시험지 인쇄 ⭐ 채택 (프론트 전용)

**본 것**: 문제지 생성 → PDF 다운로드/인쇄 → 배포 → 자동 채점 흐름. 종이 시험이
여전히 한국 내신·학원 운영의 기본 매체라는 방증이다.

**우리 형태**: 문제집 상세에 **인쇄 뷰**(`/workbook/[id]/print`)를 추가한다.
- 브라우저 인쇄(`@media print`)로 시작한다. PDF 생성 라이브러리는 **비채택**:
  서버 PDF 렌더링(폰트·수식·용량)은 유지 비용이 크고, `window.print()`가 같은
  결과물(브라우저의 "PDF로 저장")을 공짜로 준다.
- 문항지와 정답·해설지를 분리 토글한다 — 교사 배포 시나리오(족보클라우드의 배포
  단위)와 동일. 배포·수합·자동채점은 **비채택**(계정 체계가 학생 그룹을 모른다).

## 5. Quizlet — 세트 탐색·학습 모드 다변화 △ 부분 채택/보류

**본 것**: 공개 세트 검색·공유가 성장 엔진. 학습 모드(카드·주관식·게임)가 재방문을
만든다.

**우리 판단**: 문제집 탐색(검색·인기·분류 필터)은 **이미 있다**. 인기 산정이
조회수 단일이라 개선 여지는 있지만, 가중치 튜닝은 트래픽 데이터가 필요해 **보류**.
게임형 학습 모드는 문항(긴 지문·서술형)과 매체가 안 맞아 **비채택**.

## 6. 콴다 — 풀이 검색·커뮤니티 ✕ 비채택

사진 검색은 OCR·콘텐츠 DB가 본체라 우리 스택과 접점이 없다. 오답노트·유사문제
동선은 1·2번으로 흡수. 커뮤니티는 이미 댓글·리뷰가 있다.

## 7. 도그푸딩 유예 항목의 처리 (사용자 위임)

도그푸딩을 진행할 사람이 없다는 결정에 따라, "데이터가 쌓인 뒤 판단"으로 유예됐던
항목을 다음 기준으로 마감한다: **화면·수단이 없어 데이터가 애초에 쌓일 수 없는
것은 지금 만들고, 표본 크기가 판정을 좌우하는 것은 가드를 걸어 두거나 보류를
유지한다.**

| 유예 항목 (출처) | 처리 |
|---|---|
| 자기검증 판정 대시보드 — 엔드포인트만 있고 화면 없음 (`2026-08-05-selfreview-aggregation`) | **지금 만든다.** 화면이 없으면 수치가 쌓여도 아무도 못 본다 — "꺼져 있으면 데이터가 안 쌓인다" 순환의 화면판. `/me` 프로필에 카드로 붙인다(판정 0건이면 숨김 — 학습자에겐 안 보인다). |
| 서술형 축 복습 실패율 (같은 문서) | **보류 유지.** 유예 사유가 표본 크기였고, 그 사유는 사람이 아니라 데이터만 해소할 수 있다. |
| ADMIN 전역 품질 집계 (같은 문서) | **보류 유지.** 출제자가 아직 1인. |
| 생성 배치 단위 판정 요약 (`2026-08-05-ai-generation-deferred-items`) | **종결.** 후속 문서의 결정 1이 `questions.review_verdict` 컬럼으로 대체 — 채팅 경로에는 배치 경계가 없다. |

## 8. 구현 결과 (같은 날 마감)

1. ✅ 쌍둥이 문항 생성 — `CreateGenerationDto.sourceQuestionId` + 접근 검증(본인/PUBLISHED,
   과목 일치, 응시 중 차단) + 프로세서 원본 로드 + 프롬프트 변형 규칙 + 문항 상세 `VariantPanel`
2. ✅ 세션 결과 축별 리포트 — `session-report.util.ts`(순수 함수) + `getById.axisReport` +
   결과 화면 `AxisReportCard`
3. ✅ 복습 큐 누진 간격 — `review-state.util.ts` 사다리(1→3→7일, 3연속 마스터).
   기존 TRIANGLE(연속 1) 행은 다음 정답에서 7일 단계로 — 마이그레이션 없음
4. ✅ 자기검증 판정 대시보드 — `/me`의 `ReviewStatsCard`(판정 0건이면 숨김)
5. ✅ 문제집 인쇄 뷰 — `/workbook/[id]/print` + `@media print`(Tailwind `print:`) +
   정답·해설지 분리 토글, 미리보기 사이드바에 진입 버튼
