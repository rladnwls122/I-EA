## 결정 A — 지문 내장 빈칸(#43 gap 9): 마커는 **평문 규약**, 노드로 승격하지 않는다

### A-1. 마커 문법: LLM은 `[[n]]`, 저장·표시 정본은 `___(n)___`

- LLM 계약은 여전히 "평문만"이다(prosemirror.util의 대전제). 빈칸 위치는 지문 평문 안에
  `[[1]]`…`[[N]]`으로 표기시키고, 조립이 정본 `___(n)___`으로 **한 번** 정규화해 저장한다.
- 입력 문법과 정본을 나눈 이유: 모델에게는 오타 여지가 없는 단순 토큰(`[[1]]`)이 좋고,
  화면에는 밑줄+번호가 그대로 빈칸으로 읽히는 형태가 좋다. 둘을 한 문자열로 겸하려 하면
  둘 중 하나가 나빠진다.
- **`$…$` 수식 델리미터와의 비충돌** (2026-08-04에 막 들어온 #35 토크나이저):
  1. 마커 문자 집합은 `[ ] ( ) _`와 숫자뿐이라 `$`를 만들지도 소비하지도 않는다.
     역으로 수식 토크나이저는 `$`가 없으면 아예 돌지 않는다(`splitBlockMath`/`tokenizeInlineMath`
     조기 반환) — 두 문법의 트리거 문자가 서로소다.
  2. 정규화는 `buildRichDoc` **이전 문자열 단계**에서 끝나고, 치환 결과에도 `$`가 없다.
     즉 토크나이저가 보는 입력이 달라지지 않는다.
  3. 그래도 LaTeX 본문 안의 `[[...]]`(행렬 표기 등)를 건드리지 않도록, 정규화는
     **렌더 가능한 수식 구간을 건너뛴다**. 렌더 불가라 어차피 평문으로 강등될 구간은
     건너뛰지 않는다(강등 후 평문에 마커가 살아 있으면 안 되므로).
  4. `prosemirror.math.spec.ts`는 그대로 통과하며, 비충돌 자체를 `prosemirror.blank.spec.ts`가 잰다.

### A-2. 노드 승격 **안 함** (수식과 다른 판단)

| 수식(#35) | 빈칸(gap 9) |
|---|---|
| KaTeX 렌더가 필요 → 노드가 **불가피** | 밑줄+번호 → 평문 텍스트 런으로 100% 표현 |
| 공식 확장(@tiptap/extension-mathematics) 존재 | 공식 확장 없음 → 커스텀 Node + NodeView 자작 |
| 락스텝 비용을 치를 이유가 있었다 | 락스텝 비용만 남고 얻는 게 없다 |

결정적인 근거는 **실패 모드**다. 노드로 만들면 sanitize 화이트리스트·RichContent·TiptapEditor·
web/lib/prosemirror 넷 중 하나만 몰라도 Tiptap이 그 노드를 **조용히 버린다** — 빈칸이 사라진
지문은 아예 풀 수 없는 문항이 된다. 평문은 어디서도 소실되지 않는다.
(이 저장소가 "조용한 소실"을 피해 온 계보: sanitize의 throw, prosemirror.util의 "안전한 강등",
AuthoringCanvas의 검증 실패 표시.)

- 뒤집을 경우 비용: 중간. 정본 형태(`___(n)___`)가 이미 기계 판별 가능하므로 나중에 노드로
  승격하려면 조립에서 토크나이즈 한 겹만 추가하고 4곳을 락스텝으로 넓히면 된다. 저장된 데이터는
  평문이라 마이그레이션도 정규식 한 번이다.

### A-3. 문항 ↔ 빈칸 연결: LLM 계약은 `blankIndex`, 저장은 metadata + **발문 속 마커**

- LLM 응답 계약에 `blankIndex`(1부터) 구조화 필드를 추가했다(다중지문의 `passageIndex`와 같은 패턴).
  파서가 **지문 마커 집합 ↔ 문항 blankIndex 집합의 일대일**을 검증한다(개수·순서·중복·미배정·
  발문이 남의 빈칸을 가리키는 경우).
- 저장은 **스키마 추가 없이** `questions.metadata.blankIndex`(OX 스타일 표시가 이미 쓰는 자리).
- ⚠ 그런데 **응시 스냅샷(`exam_session_questions.snapshot`)에는 metadata가 실리지 않는다.**
  스냅샷 조립은 exam-sessions 소관이라 이번 작업에서 건드리지 않았다. 그래서 학습자에게 보이는
  연결 고리는 metadata가 아니라 **발문 텍스트 안의 마커**가 나른다(조립이 발문에 마커가 없으면
  앞에 붙여 보장한다). 응시 화면은 발문에서 번호를 읽어 "지문 빈칸 (n)" 배지를 띄운다.
- 스키마 컬럼은 **필요하지 않았다**. 새 컬럼 없이 끝났다.

## 결정 B — LLM 자기검증(#34 후속): **환경변수 옵트인**, 판정은 기록하되 버리지 않는다

### B-1. 옵트인 손잡이는 요청 파라미터가 아니라 환경변수(`AI_SELF_REVIEW`)

- 유예 사유가 "비용 배가"였다. 켤지 말지는 최종 사용자의 취향이 아니라 **운영 비용 결정**이므로
  DTO가 아니라 env가 맞다. 기본값은 꺼짐(`""`).
- 부수 효과로 "꺼진 경로는 종전과 완전히 동일"이 자명해진다 — DTO·프론트·`input_params` 스냅샷·
  재생성 경로를 하나도 건드리지 않았고, 스위치가 꺼져 있으면 호출 자체가 없다(테스트로 고정).

### B-2. 판정 축은 4개 — 형식 규격은 다시 보지 않는다

결정 3의 5축 중 **코드로 못 잡는 것만** 본다: 발문형식 / 오답매력도 / 난이도일관성 / 지문문항정합.
형식 규격(선지 개수·언어·정답 개수)은 파서가 이미 검증했으므로 토큰을 태워 다시 묻지 않는다.
축 이름은 코드 상수(`REVIEW_AXES`)로 고정해 프롬프트가 흔들려도 기록이 통계로 모이게 한다.

### B-3. 판정 결과 사용: **기록만 한다**(버리지도, 재생성하지도 않는다)

- REVISE 판정이어도 문항은 그대로 저장한다. 재생성은 비용을 한 번 더 배가시키고, 조용히 버리는 건
  이 저장소가 일관되게 피하는 실패 모드다. 어차피 생성물은 `DRAFT`로 사람 검수를 기다린다 —
  검수자에게 **근거를 붙여 주는 것**이 이 기능의 값이다.
- 기록 자리: `questions.metadata.review = { model, at, verdict, axes, issues }`. REVISE는 서버 로그에도
  경고로 남긴다.
- 판정 호출이 실패하면(모델 오류·파싱 실패·타임아웃) **생성 배치를 실패시키지 않는다** — 옵션을 켠
  것만으로 생성이 깨지면 안 된다. 대신 `verdict: 'ERROR'`로 남긴다. "판정했는데 통과"와 "판정을 못 했다"를
  뭉개면 기록이 거짓말이 된다.

### B-4. 판정용 모델은 **분리하지 않는다**

2026-08-04 결정 6(`GEMINI_TUTOR_MODEL` 분리 보류)과 같은 판단이다. `GEMINI_MODEL` 기본값이 이미
flash급이라 지금 나누면 같은 값을 가리키는 두 번째 설정 손잡이만 생긴다. 생성 모델을 pro급으로
올리는 결정이 실제로 날 때 그 커밋에서 함께 나눈다. 분기점은 `GeminiLlmService.selfReviewModel`
한 곳에 모아 뒀다.
