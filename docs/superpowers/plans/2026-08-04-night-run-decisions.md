## 결정 1 — #39 복습 루프 '완성' 마감선

### B-1. 복습 재풀이의 개인 통계 오염 → **1차 응시만 집계한다 (고침)**

- 결정: `me.service.notes()`의 채점 이력 조회에 `session.isReview: false` 필터를 추가.
  `summary.solved/correct/scorePercent`, `bySubject/byType/byKeyword` 전부 1차 응시 기준.
- 코치 관점 근거: 오답노트 통계의 용도는 "내 약점이 어디인가"다. 복습은 정의상 틀린 문제만
  다시 푸는 행위라, 섞이는 순간 과목별 정답률이 실력과 무관하게 출렁인다(#37 약점 진단이
  이 데이터를 신호로 쓸 예정이라 상류 오염은 지금 막아야 싸다).
- 복습 세트 조립(`wrongQuestions` + 복습 상태)은 영향 없음 — 복습 상태는 별도 테이블이고
  전이는 계속 복습 세션에서도 일어난다(#20 결정 유지).
- 뒤집을 경우 비용: 필터 한 줄 제거. 데이터 손실 없음.

### B-2. 자기채점 안 한 서술형 → **미채점 카운트를 노출한다 (리마인드만, 큐 편입은 안 함)**

- 결정: `notes()` 응답 `summary`에 `ungradedCount`(자기채점 대기 서술형 답안 수) 추가,
  프론트 오답노트 사이드바에 "자기채점을 기다리는 서술형 N문항" 안내 + 해당 세션 결과로 가는 동선.
- 큐에 자동 편입하지 않는 이유: 상태 전이의 입력이 자기채점이다. 채점 없이 큐에 넣으면
  "맞았는지 모르는 문제를 복습하라"가 되는데, 이는 복습이 아니라 채점 독촉이다. 독촉은 독촉대로 보여준다.
- 뒤집을 경우 비용: 카운트 필드는 남겨도 무해. 큐 편입으로 확장 시 이 카운트가 그대로 입구가 된다.

### B-3. `/me/notes` 무제한 로드 → **서버 상한 + 최신순 정렬만 (페이지네이션은 안 함)**

- 결정: 채점 이력 조회에 `orderBy: gradedAt desc` + `take: 500` 상한. 응답에 `truncated: boolean` 명시.
- 진짜 페이지네이션을 지금 안 하는 이유: 프론트 복습 큐 조립이 이 응답 하나에 의존한다.
  커서 페이지네이션은 복습 큐 API를 백엔드로 옮기는 재설계(별도 티켓감)와 함께 해야 이중작업이 안 된다.
  500은 "복습 큐 상한 100 + 통계 표본"으로 충분하고 응답 크기 폭주만 막는 보험.
- 뒤집을 경우 비용: 상수 조정 또는 제거만.

### C. 알림/리마인더 → **가장 싼 중간값 채택: due 배지 (새 인프라 없음)**

- 결정: 사이드바(전역 내비)의 오답노트 아이콘에 due 문항 수 배지. `GET /me/notes/summary` 같은
  경량 엔드포인트 신설(전량 로드 없이 due 카운트만) 후 프론트 내비에서 폴링 없이 마운트 시 1회 조회.
- 푸시·메일은 이번 로드맵 밖: 인프라(웹푸시 구독, 메일러) 대비 도그푸딩 검증이 안 된 상태.
  배지로 "들어오면 보이는" 수준을 먼저 확보하고, 도그푸딩에서 그래도 빼먹으면 그때 푸시를 단다.
- 뒤집을 경우 비용: 배지는 어차피 푸시의 전제 데이터(경량 due 조회)라 버려지는 작업이 없다.

## 결정 2 — #43 시험별 문항 형식 템플릿

### 데이터 모델: **DB 테이블이 아니라 코드 레지스트리 (exam-format.ts 확장)**

- 근거: 템플릿은 시험 관행이라 변경 빈도가 낮고, 버전 관리·리뷰가 필요한 값이다(프롬프트와
  묶여 있어 코드와 함께 테스트돼야 함). 이미 `EXAM_FORMATS` 레지스트리가 같은 판단으로 코드에 있다.
  운영자가 런타임에 템플릿을 편집할 요구가 생기면 그때 DB로 승격(레지스트리 구조를 그대로 옮기면 됨).
- 템플릿 스키마(`FormatTemplate`):
  - `id`(안정 키, 예: `csat-korean-passage-set`), `label`, `examTypes[]`(노출 조건), `description`
  - `structure`: `passageCount`(0/1/2 — 2는 (가)(나)·이중지문), `questionsPerPassage`(권장 범위),
    `choiceCount`, `answerMode`(`single` | `multiple`), `language`(OutputLanguage), `questionType` 힌트
  - `promptHints[]`: 발문 패턴·소재·오답 설계 지시(기존 EXAM_FORMATS hints보다 구체)
- DTO: `CreateGenerationDto.templateId?` 추가. 템플릿이 기본값(선지 수·언어·includePassage·문항 수 범위)을
  깔고, 사용자가 명시한 개별 파라미터가 항상 우선. 템플릿 목록은 `GET /ai-generations/templates?examType=`으로 노출.
- 1차 템플릿 목록(#36 노력 순위 1~2위 = 공짜 시험부터):
  1. `csat-korean-passage-set` 수능 국어 지문세트형 (5지, 지문1, 3~6문항)
  2. `csat-inquiry-data` 수능 탐구 자료해석형 (5지, ㄱㄴㄷ 합답 허용)
  3. `csat-integrated-passages` 수능 국어 (가)(나) 주제통합 (지문 2)
  4. `school-multi-answer` 내신 복수정답형 "모두 고른 것은?" (5지, answerMode: multiple)
  5. `school-essay-condition` 내신 서술형 조건제시형 (주관식)
  6. `civil-9-reading` 공무원 9급 독해·추론형 (4지)
  7. `civil-9-source` 공무원 9급 사료·판례제시형 (4지)
  8. `ncs-module` NCS 모듈형 (4지) / 9. `ncs-psat-data` NCS 자료해석형 (4지, 텍스트 표)
  10. `toeic-part5` 토익 Part 5 어법형 (4지, en, 지문 없음)
  11. `toeic-part7-single` 토익 Part 7 단일지문 (4지, en, 실무 문서)
- 구조 강제 해체 범위 (이번에 푸는 것):
  - **복수정답(gap 4)**: 채점(`grading.util.ts`)은 이미 정답 집합 비교라 호환. 생성 검증의
    "정답 정확히 1개"를 `answerMode`에 따라 "1개 이상"으로 완화 + 프롬프트에 복수정답 지시.
  - **다중지문(gap 3)**: 스키마는 이미 1:N(AiGeneration→Passage[], Question.passageId) — LLM 응답
    계약을 `passages[]` + 문항별 `passageIndex`로 확장하고 프로세서가 지문별로 생성. 마이그레이션 불필요.
  - **지문 내장 빈칸(gap 9, 토익 Part 6)**: 이번엔 안 푼다 — 빈칸 위치 규약(마커) 설계가 필요하고
    Part 5·7 템플릿이 먼저 검증돼야 한다. 템플릿 목록에서 제외.
  - **채점기준표(gap 8, 내신 서술형)**: 스키마 신규 모델링이라 이번 범위 밖. 서술형 템플릿은
    "모범답안을 explanationText에" 수준(기존 힌트)으로 시작.

## 결정 3 — #34 '시험급 문제' 품질 기준

코치 관점에서 "시험급"의 조작적 정의 — 아래 5개 축을 시스템 프롬프트의 품질 체크리스트로 주입하고,
검증 가능한 것은 코드 검증으로 끌어내린다.

| 축 | 기준 | 반영 방법 |
|---|---|---|
| 발문 형식 | 실제 기출 발문 패턴("~로 가장 적절한 것은?"), 부정발문은 "않은/없는" 밑줄 관행 | 템플릿 promptHints + 시스템 프롬프트 |
| 오답 매력도 | 오답은 "그럴듯한 오해"에서 나와야 함 — 각 오답이 어떤 실수·혼동에서 나오는지 설계 지시. 해설이 정답 근거+대표 오답의 함정을 다룸 | 시스템 프롬프트 품질 체크리스트 |
| 난이도 일관성 | difficulty 1~5의 조작적 정의(1: 개념 확인 단답 ~ 5: 다단계 추론·복합 자료)를 프롬프트에 명시 | 시스템 프롬프트 |
| 지문-문항 정합 | 지문형 문항은 지문 없이 못 풀어야 함(지문 무관 상식 문항 금지) | 시스템 프롬프트 + 지시 |
| 형식 규격 | 선지 개수·언어·단일/복수정답이 요청과 일치 | 이미 코드 검증(파서) — 유지 |

- 격차 진단(현행): 형식 규격은 파서가 잡지만 나머지 4축은 프롬프트에 지시 자체가 없다.
  1차 마감선(도그푸딩 체감)은 "발문 형식 + 오답 매력도" 두 축 주입까지. LLM-판정(자기검증 2차 호출)은
  비용이 배가라 도그푸딩에서 품질 미달이 확인되면 후속.

## 개선 아이디어 백로그 (이번 세션 범위 밖 — 아침에 검토용)

1. **복습 큐 API의 백엔드 이관** — 지금 프론트가 `/me/notes` 전량을 받아 큐를 조립한다.
   `GET /me/review-queue?limit=100`으로 옮기면 B-3의 진짜 페이지네이션이 풀리고 due 배지와 데이터 출처가 통일된다.
2. **생성 품질 회귀 테스트 하네스** — 템플릿별 골든 프롬프트 몇 개를 두고 파서 통과율·형식 준수율을
   주기 측정(LLM 호출 비용 때문에 CI 밖, 수동 스크립트). #34 후속 마감선 판단의 근거 데이터가 된다.
3. **'유형' Tag ↔ '출제유형' 카테고리 중복 정리** — #24 소관으로 남아 있음. 템플릿 id와 '출제유형' Tag를
   1:1로 잇는 매핑을 두면 생성 시 자동 태깅이 가능(문제 생성→약점 진단(#37)의 신호 연결 고리).
4. **서술형 채점기준표 모델** (gap 8) — `questions.rubric Json?` (기준·배점 배열) + 자기채점 UI가
   기준별 체크로 부분점수 계산. 내신 서·논술형 30% 의무 반영 고려하면 내신 페르소나에겐 필수적.
5. **미채점 서술형 리마인드 강화** — B-2의 카운트를 due 배지에 합산할지(오늘 할 일 = 복습 + 채점).
6. **캔버스(#41) 선행 조각** — 이미지 presign 파이프라인을 캔버스 편집기에 붙이는 작업은 템플릿과
   독립적이라 먼저 뺄 수 있음. 수식(#35)은 백/프론트 동시 커밋 함정 때문에 단독 세션 권장.
