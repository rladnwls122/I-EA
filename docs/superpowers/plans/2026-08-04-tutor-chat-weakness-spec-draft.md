# 복습 튜터 챗(#40)·약점 진단(#37) 스펙 초안

> 야간 자율 세션 산출. 로드맵 ④·⑤ 결정 티켓의 초안 — 확정 아님, 아침 검토용.
> 시니어 개발자 + 수험생 코치 관점의 제안이며, 각 결정에 대안·비용을 병기한다.

## A. 오답 복습 AI 튜터 채팅 (#40)

### 역할 정의 (코치 관점)

오답 복습에서 학습자가 실제로 막히는 질문은 세 종류다:
1. "왜 내 답이 틀렸나" (오답 원인 — 가장 흔함)
2. "왜 이게 정답인가" (해설이 안 읽힘)
3. "비슷한 걸 또 틀리지 않으려면" (전이 — 개념·유형 일반화)

튜터 챗의 마감선은 이 셋에 답하는 것. 잡담·전 과목 과외로 확장하지 않는다(비용·품질 통제 불가).

### 컨텍스트 범위 (핵심 결정)

- **주입할 것**: 해당 문항 스냅샷(발문·선지·정답·해설 평문), 학습자의 제출 답, 오답 여부,
  문항의 subjectDetail·키워드, 학습자가 단 주석(reasonCode·memoText — 오답 원인 자가 진단).
- **주입하지 말 것**: 전체 학습 이력, 타 문항. 토큰 비용 대비 답변 품질 기여가 낮고,
  약점 진단(#37)이 별도 축으로 다룬다.
- 근거: authoring-chat의 기존 패턴(문항 요약 절단 주입)이 그대로 재사용 가능. 인프라 신규 조각 없음.

### UX (프로토타입 방향)

- 진입점: 오답노트 문항 카드 + 세션 결과 화면 문항 카드의 "AI에게 물어보기" 버튼.
- 패널: authoring-chat과 동일한 SSE 스트리밍 채팅 패널 재사용(우측 슬라이드 오버).
  첫 진입 시 선제 메시지: 학습자 답과 정답 차이를 한 문단으로 짚어줌(1회 무료 호출 — "왜 틀렸나"가
  가장 흔한 질문이므로 선제 제공이 UX 이득).
- 히스토리: Redis, 키 `tutor:${userId}:${questionId}`, TTL 6h(authoring 관행 동일). DB 영속 안 함(1차).

### 백엔드 설계

- `POST /questions/:id/tutor-chat` SSE — authoring-chat.service 구조 복제(레이트 리밋 포함).
  프롬프트만 다름: "너는 오답 코치. 정답을 다시 알려주는 게 아니라 학습자의 오개념을 짚는다.
  답변은 ① 왜 그 선지가 매력적으로 보였나 ② 정답 근거 ③ 다음에 같은 유형을 만날 때 확인할 것 순."
- 모델·비용: 생성보다 저렴해야 함 — GEMINI_MODEL과 별개로 `GEMINI_TUTOR_MODEL`(기본 flash급) 권장.
  레이트 리밋: 유저당 시간당 N회(도그푸딩으로 조정, 초기 30).
- 권한: 본인이 푼 문항(답안 존재)에만 허용 — 무단 문항 열람 방지·컨텍스트 성립 조건.

### 비범위 (1차)

- 수식 렌더링(수학 튜터) — #35 파이프라인 합류 후.
- 대화 영속·이어보기, 튜터 대화 기반 통계.

## B. 약점 진단 — 신호 정의와 추천 방식 (#37)

### 신호 정의 (무엇을 약점이라 부르나)

이번 세션에서 통계 오염을 제거했으므로(1차 응시만 집계, #39 B-1) 신호의 신뢰도 전제가 확보됨.

| 신호 | 원천 | 상태 |
|---|---|---|
| 분류축 정답률 (subjectDetail·키워드·출제유형 Tag별) | graded 1차 응시 답안 | 데이터 있음 — bySubject/byKeyword 이미 집계 |
| 오답 원인 분포 (reasonCode: 개념부족/실수/시간부족…) | 주석(annotations) | 데이터 있음 — byReason 이미 집계 |
| 복습 실패율 (복습에서도 또 틀림 = X→X 전이 비율) | review-state 전이 이력 | **전이 이력 테이블 없음** — 현재 상태만 저장. 이력 컬럼/테이블 필요 |
| 미도달 (풀어본 적 없는 분류) | 분류 대비 답안 존재 여부 | 계산 가능 |

- 최소 표본 규칙 필수: 분류축당 답안 N<5면 "진단 불가(더 풀어보세요)"로 표시 — 소표본 정답률로
  약점 단정하면 코치로서 오진. UI에 표본 수 병기.
- 약점 점수(1차 제안): `(1 - 정답률) × log(1+표본수)` 정렬 — 많이 틀렸고 표본도 있는 축이 상위.
  '실수' reasonCode 비중이 높은 축은 "개념 약점"이 아니라 "훈련 부족"으로 라벨 분리(처방이 다름).

### 추천 방식 (진단 → 행동 연결)

로드맵 fog였던 "진단 결과 → 시험 세션 자동 생성" 연결:
- 진단 카드마다 "이 약점 공략 세트 풀기" 버튼 → 기존 `POST /exam-sessions` 필터 모드
  (subjectId + 해당 분류 조건 + questionCount 10)를 그대로 호출. **신규 API 불필요** — 필터 모드가
  subjectDetail/Tag 필터를 지원하는지만 확인·보강하면 됨(현재 difficulty/type/tag 지원 — subjectDetail 필터 추가 필요).
- 풀 문항이 부족한 분류는 AI 생성 유도(#43 템플릿과 연결: 해당 시험 템플릿 프리셋 + subjectDetail 지정) —
  "약점인데 풀 게 없다"를 콘텐츠 생성 수요로 전환하는 게 이 제품의 학습 루프 완성점.

### 화면 (1차)

- `/notes` 대시보드에 "약점 TOP 3" 카드(분류명·정답률·표본수·처방 버튼). 별도 페이지는 2차.

### 선행 작업 (이 티켓의 실제 코드 범위)

1. 답안-분류 집계에 subjectDetail·출제유형 Tag 축 추가(me.service — 현재 bySubject/byType/byKeyword뿐).
2. exam-sessions 필터 모드에 subjectDetailId 필터 추가.
3. (선택) review-state 전이 이력 기록 — 복습 실패율 신호용. 스키마 추가라 별도 결정.

## 우선 구현 제안 순서

로드맵 순서(④ 튜터 챗 → ⑤ 약점 진단)를 유지하되, ⑤의 선행 작업 1·2는 작고 독립적이라
④와 병행 가능. ③까지의 이번 세션 작업으로 데이터 신뢰도 전제는 이미 확보됨.
